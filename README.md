# c-bot

웹 브라우저에서 쓰는 코딩 에이전트입니다. 워크스페이스를 고른 뒤 세션에서 파일을 읽고 고치고 명령을 실행합니다. 봇 모드에서는 역할이 다른 에이전트들이 서로 메시지를 주고받으며 일을 나눕니다.

런타임은 [Bun](https://bun.sh)입니다.

## 기능

- 로컬 웹 서버와 앱 셸 (왼쪽 프로젝트 트리, 아래에 봇 목록, 서버 연결 상태)
- 세션 로그가 대화의 기준이다. 새로고침해도 같은 대화가 복원된다. 응답을 기다리는 동안 로그에 **생각 중**이 보인다
- 대화 맨 아래를 보고 있을 때만 새 응답을 따라 내려간다. 위로 스크롤해 이전 대화를 읽는 동안에는 위치를 유지하고, 맨 아래로 돌아오면 자동으로 따라간다. 분할 보기에서도 각 봇 대화가 독립적으로 동작한다
- **설정 → 모델**에서 CLIProxyAPI·OpenAI·DeepSeek 등 정식 프로바이더를 추가하거나 커스텀 게이트웨이를 넣는다. 기본 모델은 검색해서 고른다
- **프로젝트**: 왼쪽 트리에서 폴더를 고른다. `+`는 OS 폴더 창을 연다. 폴더를 복사하지 않고 그 경로를 연다. 코딩 세션은 그 프로젝트 아래에 매달린다. 목록은 처음 연 순서를 유지한다. 폴더를 눌러도 열린 대화는 그대로다. 세션 행의 점은 다른 세션이 일하는 중이면 천천히 깜박이고, 끝나면 켜진 채 멈추며, 그 세션을 열면 사라진다. 리드가 부른 전문 봇이 아직 도는 동안도 작업 중으로 본다. 행의 `×`로 세션 또는 프로젝트를 지운다. 프로젝트 삭제는 목록과 그 폴더의 코딩 세션만 지우고, 디스크의 폴더는 남긴다
- 도구: `read_file`, `write_file`, `edit_file`, `list_dir`, `grep`, `glob`, `bash`, `todo_write`, `task`
- 도구 결과는 기본으로 접혀 있다. **도구 결과**를 누르면 전체 내용을 펼치고, 내부 스크롤 없이 대화와 함께 스크롤한다. 작업 목록 등 결과가 JSON 객체나 배열이면 들여쓰기와 줄바꿈을 적용해 보여 준다
- `bash`는 기본 승인 대기. 허용/거절은 대화 카드에서 한다. 카드의 **이 세션에서 `bun test` 허용**은 서버가 켜져 있는 동안 그 세션에서 같은 접두어로 시작하는 명령을 묻지 않고, **항상 허용**은 `config.yaml`의 `approval.allow`에 적어 모든 세션에서 묻지 않는다. 접두어는 프로그램 이름이고, `bun`·`git`·`npm` 같은 러너는 하위 명령까지다 (`git status`). `&&`·`;`·`|`로 이은 명령은 조각마다 허용 접두어가 있어야 하고, `$( )`·백틱·리다이렉션이 있으면 늘 묻는다
- 턴이 도는 동안에도 입력창이 열려 있다. 그때 보낸 메시지는 컴포저 위 **대기열**에 쌓였다가 턴이 끝나면 차례로 들어간다. 대기 중인 줄을 누르면 다시 입력창으로 돌아오고, `×`는 대기열에서 뺀다. 대기열은 세션마다 따로다
- 입력창에서 `/`를 치면 명령 목록이 뜬다. `/help` 명령 목록, `/status` 세션·모델·컨텍스트 상태, `/compact [지시]` 지금까지 대화 요약, `/clear` 컨텍스트 비우기, `/model [모델]` 모델 보기·바꾸기, `/approvals [prompt|allow|forget <명령>|reset]` 승인 정책과 허용 명령 보기, 항상 허용에서 빼기, 이 세션의 허용 지우기, `/bots` 로스터, `/init` 이 프로젝트의 AGENTS.md 초안. 명령의 답은 로그에 남지만 모델 히스토리에는 들어가지 않는다. 목록에 없는 `/`로 시작하는 글(`/Users/me/app` 같은 경로 포함)은 그대로 모델에게 간다
- 대화가 길어지면 컨텍스트가 차기 전에 스스로 **요약**한다. 요약은 로그에 한 줄로 남고, 펼치면 모델이 이어 보는 요약 본문을 읽는다. 원래 대화는 지워지지 않아 새로고침하면 그대로 보인다. 임계값과 요약 뒤에 원문으로 남길 턴 수는 `$CBOT_HOME/config.yaml`의 `context`에서 바꾼다
- 정지 단추(또는 `⌘/Ctrl+Enter`)는 도는 턴을 그 자리에서 멈춘다. 멈출 때 입력창에 쓴 게 있으면 기다리지 않고 바로 보낸다. 멈춘 자리에는 로그에 **중단됨**이 남고, 다음 턴의 모델도 답이 잘렸다는 것을 본다

- 고정 **leader** 봇이 사용자와 대화한다. 모델·Effort·프롬프트만 바꿀 수 있고 삭제할 수 없다. 봇마다 SQLite 메모리가 있고, 봇을 눌러 연 설정 창 오른쪽 **메모리**에서 목록을 보고 만든다. 각 기억은 **제목**, 언제 꺼내 쓸지 **설명**(검색), 실제로 기억할 **내용**이다. 새 기억은 **추가**, 고친 기억은 **수정**, 목록 행의 `×`로 지운다. 아래 **저장**은 봇 이름·모델·프롬프트다. 턴이 시작되면 제목·설명으로 CJK 바이그램 FTS5(BM25) 검색해 내용을 로그에 넣는다. 모델은 `memory` 도구로도 쓴다.
- 봇마다 **스킬**이 있다. `$CBOT_HOME/bots/<봇 id>/skills/`에 `이름.md` 또는 `이름/SKILL.md`를 두면 이름순으로 그 봇의 시스템 프롬프트에 들어간다. 봇 설정 창에 읽힌 스킬 이름이 보인다. 파일을 바꾸면 다음 턴부터 반영된다
- 전문 봇은 로스터로만 둔다. 직접 대화하지 않고, 리드가 `message_agent`로 부른다. 봇 설정 창의 **로스터에서 숨김**을 켜면 리드가 보는 로스터와 `@` 자동완성에서 빠지고 사이드바에서 흐리게 보인다. 핸들로 직접 부르면 여전히 받는다. 리드는 숨길 수 없다. 코딩 세션은 리더 모델로 돈다. 모델은 사이드바 `@leader`에서 고른다. 봇마다 모델과 Effort를 고른다.
- 봇끼리 주고받는 턴이 프로바이더의 일시 장애(속도 제한, 서버 오류, 타임아웃, 컨텍스트 초과)로 실패하면 같은 대화에서 한 번만 다시 시도한다. 시도 사실은 로그에 남는다. 인증·쿼터·설정 오류는 다시 시도하지 않는다. 사용자가 직접 보낸 메시지의 턴은 바로 실패를 보여 준다
- 코딩 세션을 열면 리드 대화와, 그 세션에서 부른 전문 봇 칸을 탭 또는 **분할**로 본다. 분할에서는 봇마다 흰 메모장처럼 놓고 크기를 바꾸거나 접을 수 있다. 제목을 끌어 옮기고, 제목이나 가장자리에서 스크롤하면 크기가 바뀐다. 위치·크기·접힘은 세션마다 기억한다. 세션을 바꾸면 봇 칸도 그 세션 것이다. 전문 봇 칸은 보기만 하고, 메시지는 리드에게만 보낸다
- 모델 답은 마크다운으로 보여 주고, ` ```mermaid ` 블록은 그림으로 그린다
- 분할 보기의 대화와 스크롤바 영역에서 휠을 돌리면 대화만 스크롤한다. 창 크기는 제목이나 스크롤바 바깥의 조절 여백에서 바꾼다
- 입력창에서 `@`를 치면 봇과 프로젝트 파일을 찾는다. 고른 파일은 메시지에 첨부되어 모델이 읽는다
- 코딩 세션을 열면 오른쪽에 **Git / 파일 / 작업** 패널이 있다. Git은 현재 브랜치와 변경 파일에 더해 브랜치·리모트·태그 목록과 최근 커밋 기록을 보여 준다. 커밋을 누르면 작성자와 메시지 본문, 그 커밋이 바꾼 파일과 증감 줄 수를 펼쳐 본다. 패널 왼쪽 가장자리를 끌어 너비를 조절하고, 조절한 너비는 다음에 열 때도 유지된다. 파일은 폴더를 타고 열어 보고, 마크다운은 mermaid를 그린다. **작업**은 그 세션의 공유 할 일 판이다. 리드와 전문 봇이 `task` 도구로 등록·조회·완료하고, 판에 없어야 할 줄은 지운다. 담당과 요청자를 구분해 다른 봇이 시킨 미완료 일을 본다. 큰 일은 하위 작업으로 쪼갠다. 판은 두 단계까지라 하위 작업은 다시 쪼개지 않는다. 판은 봇의 것이라 사람은 누가 무엇을 맡아 어디까지 갔는지 읽기만 한다. 봇이 판을 고치면 목록이 바로 따라 바뀐다

Git 패널의 **변경사항 리뷰**에서 스테이지된 파일·아직 스테이지하지 않은 파일·추적하지 않는 새 파일을 선택하면 줄 단위 diff, 이전/이후 줄 번호, 추가·삭제 줄 수를 봅니다. 삭제와 이름 변경도 확인할 수 있습니다. 바이너리는 안내만 표시하고, 큰 diff는 일부만 표시합니다. 도구 실행 후 자동 갱신되며 외부에서 수정한 내용은 **새로고침**으로 확인합니다.

**세션 변경 기록**은 리드와 그 세션의 전문 봇이 성공한 파일 쓰기·편집 도구 기록을 파일별로 집계합니다. 셸 실행 횟수는 별도로 표시하며, 셸이 수정한 파일은 집계하지 않습니다. 현재 Git diff는 작업 폴더 기준이므로 세션 시작 전이나 다른 세션의 변경도 포함합니다. 세션 변경 기록은 수정 이력이며 세션만의 순수 변경량을 뜻하지 않습니다.

## 요구 사항

- [Bun](https://bun.sh) 1.4 이상 (`bun --version`)
- 모델 턴을 쓰려면 설정에 프로바이더와 API 키가 있어야 한다

## 실행

```sh
bun install
cp .env.example .env
bun run dev
```

`bun run dev`는 API 서버와 개발용 Vite를 나란히 켭니다. 브라우저는 터미널의 `c-bot listening` 주소를 엽니다. 포트는 `.env`의 `CBOT_PORT`입니다 (기본 `3080`). Vite가 찍는 `http://127.0.0.1:5173`은 UI 핫리로드 작업자라 앱 주소가 아닙니다. 개발 중에는 웹 코드를 저장하면 새로고침 없이 화면이 바뀌고, 서버 코드를 저장하면 서버만 다시 떠서 열린 화면이 스스로 다시 붙습니다.

1. **설정 → 모델**에서 **커스텀 프로바이더 추가**로 ID, Base URL, 모델, API 키를 넣습니다. 저장한 키는 `$CBOT_HOME/.env`의 `{ID}_API_KEY`로만 남고 브라우저로 다시 내려오지 않습니다.
2. 왼쪽 **프로젝트** `+`는 운영체제 폴더 창을 엽니다. 고른 폴더를 프로젝트로 씁니다. 창을 쓸 수 없으면 대화 상자에서 최근 폴더나 경로를 고릅니다. 프로젝트 행의 `+`는 그 폴더에 새 세션을 만듭니다.
3. 메시지를 보냅니다. 응답이 오는 동안 로그에 **생각 중**이나 흘러나오는 답이 보입니다. 그 사이에 적은 메시지는 대기열에 쌓였다가 턴이 끝나면 들어가고, 정지 단추는 턴을 멈춥니다.

저장소 루트 `.env`의 `*_API_KEY`도 서버가 읽습니다 (`bun run dev`의 cwd와 무관하게 저장소 루트를 연다).

```sh
bun test
bun run typecheck
```

## 환경 변수

시크릿과 프로세스 위치만 환경 변수로 둡니다. 값은 `.env`에 넣고 커밋하지 않습니다. 이름은 [`.env.example`](.env.example)과 같습니다.

모델 id, Base URL, 프로바이더 목록, 승인 모드, 컨텍스트 압축은 `$CBOT_HOME/config.yaml`입니다. 기본 승인 모드는 `prompt`입니다. `approval.allow`는 `prompt`에서도 묻지 않고 실행할 명령 접두어 목록이고, 승인 카드의 **항상 허용**이 여기에 적습니다. `context.autoCompact`는 자동 요약 여부, `context.maxTokens`는 컨텍스트 한도 추정치(기본 `128000`), `context.compactAt`은 요약을 시작하는 비율(기본 `0.8`), `context.keepRecentTurns`는 자동 요약 뒤에도 원문으로 남길 턴 수(기본 `2`)입니다. 프로바이더 API 키는 설정 화면에서 넣으면 `$CBOT_HOME/.env`에 `{ID}_API_KEY`로 저장됩니다.

| 이름 | 기본값 | 의미 |
|---|---|---|
| `CBOT_HOME` | `~/.c-bot` | 런타임 데이터 루트 (세션 DB, config.yaml, .env) |
| `CBOT_HOST` | `127.0.0.1` | 서버 바인드 주소 |
| `CBOT_PORT` | `3080` | 서버 포트. Chrome이 막는 포트(`6000` 등)는 쓰지 않는다 |
